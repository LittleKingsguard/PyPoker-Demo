## 1. The nine steps (D3)

One pass of `run`, in this order, for any configuration — a registry rung or one written to `ladder.md` §3 and in no design document (`loop.md` §3, FAM-15.1). Steps 3–8 repeat per variant and per seed; steps 1, 2 and 9 happen once.

1. **Resolve, refusing what the run would discard.** A string goes through `rung(name)` (`registry.md` §5). A mapping is used as it stands, refused in this order and always naming the key or the value it saw: the shape and the keys it reads (`name`, `variants`, `pool`, `seeds`, `samples`, `device`, `table`, `game`) and then the seed set's and budget's values (§5, `surface.md` §4); each entry's `backend`, `encoding` and `architecture` (`check_variant`); every declared `param_budget` that is not a positive integer; the declarations a run would not use — the `hyper` keys, a `learning_rule`, a `utility` or a `counterfactual` no catalogue `agents.learners()` publishes carries, a `game` no catalogue `engine.game_shapes()` publishes carries, and the `snapshot_every` of either level, each at both levels (§2) — and, for two entries, the **six** settings both arms must share (§6). Then the shape is resolved **once**, `shape = _game(configuration)`: the `game` at the configuration, else at its first variant entry, else the catalogue's first shape, an uncatalogued name being `UnknownShape` naming the level, the name and every declared name and never defaulted (`shapes.md` §2–§3, D-29). **No bound of the pass's is checked here**: the pass samples the run rather than replaying it whole, so a budget above 2,000 hands is a run this step accepts and `greedy._sample(budget)` at step 8 says how many hands the pass plays (`greedy.md` §1, §4, `sizing.md` §4, ASM-38, D-36). Then the pool, at step 2. No step after this one sees a configuration this one refused (`errors.md` §2, `counterfactual.md` §6, D-43).
2. **Freeze the pool before the first hand.** The declaration is `{"members": <config["pool"]["members"] filtered to versions whose `path` names a readable file>, "m": <the pool entry's declared bound, else the league's M>, "frozen": True, "game": <the run's shape>}`, plus `"baselines"` — named catalogue baselines the configuration admits — when its `pool` entry declares one, forwarded as it stands and never defaulted here; it goes to `evaluation.build_pool` and `evaluation.pool_members` reads the membership back. The shape is forwarded because a pool is one shape's: a member of another shape is that entry point's `ShapeMismatch`, refused before a hand (`records.md` §8, `shapes.md` §3, `evaluation/pool.md` §1, D-29). No snapshot of this run enters it (D-16, ASM-16, ASM-32, `registry.md` §3, D-21).
3. **Build the variant under the shape, the rule, the utility and the counterfactual it declares.** `features.build_encoder(entry["encoding"], shape=shape)`, then `features.observation_spec(encoder)` — the second call is the boundary check the run makes on a value it did not build, so a spec that is not an encoder's is refused there rather than at the first hand, while the encoding a spec reports is `build_encoder`'s own consequence of the encoding it was handed and is not re-compared here (`surface.md` §4, `features/surface.md` §5). Per seed, `agents.build_learner({"backend", "architecture", "seed", "encoder", "game"})` with the run's seed as the learner's own seed, plus `"learning_rule"`, `"utility"` and `"counterfactual"` when the entry — else its configuration — names them; a variant naming any of the three passes no key and `agents` builds that catalogue's first, so the spec is a declaration and never a member this module substituted (ASM-2, D-19, D-20, D-43, `agents/surface.md` §4, `protocol.md` §4). **The counterfactual is the one of the three whose key is what it means**: it is added only when it was declared, so a variant naming nothing is built exactly as it was before D-43 and writes the container it always wrote (`counterfactual.md` §6, §9). `game` is always passed and is the resolved name: the head is as wide as that shape's descriptor count, so the parameter count follows the shape and no backend holds a `3` of its own (`sizing.md` §6, `shapes.md` §2, D-29), and the policy this loop assembles decodes its index in the same vocabulary (`episode.md` §2).
4. **Seed the work, not the arm.** Hand *i* of a run at `seed` is dealt at `_deal_seed(seed, i)` and draws its opponents at `_opponent_seed(seed, i)`, both functions of the run seed and *i* alone, so the hand — its deal, its draw and its seat — is a function of `(seed, i, shape)` and of nothing else (`seeds.md` §2, `episode.md` §1). The draw is `_hand`'s at step 5 and not a step of its own: `evaluation.opponent(pool, `_opponent_seed(seed, i)`)` on a two-seat shape, and one counted draw of `seats − 1` distinct members at that same seed on a shape with more (`evaluation/pool.md` §4, `seats.md` §4, ASM-16, ASM-43) — the same draw the pass will replay at the same hand (`greedy.md` §1).
5. **Play the hand through `engine`.** The hand is `episode._hand(pool, shape, seed, i, policy)`, returning the episode and the seat the learner held in it: it derives both seeds, seats the learner at `_seat(i, shape)` — `i mod seats`, over the seat count `engine.game_config` declares and never a number written here — and fills the other seats, so it is the loop's and the pass's one way of dealing a hand (`episode.md` §1, `seats.md` §4, ASM-43, ASM-44). The seating is the shape's: `engine.play_hand(hand_seed, seat0, seat1, shape=shape)` with the learner in `_seat`'s place and the hand's opponent in the other on a two-seat shape, and `engine.play_hand(hand_seed, seats=(...), shape=shape)` with the learner's policy inserted at that seat and `seats − 1` drawn members in seat order on a shape with more (`engine/surface.md` §10, `e2e-surface.md` §3.1, `shapes.md` §2, §8, D-29, D-33). The learner's policy is `_learner_policy(learner, encoder, shape)` (`episode.md` §2), and both sides and every drawn opponent play the run's own game and never the engine's default.
6. **Learn once per hand.** The episode's decisions for the learner's own seat become `records.md` §4 transitions and go to `agents.learn` as one batch, in the caller's order, neither sampled nor shuffled (`episode.md` §5, ASM-7); the transition step is handed `_trained_utility(config, entry)`, the utility the variant is trained on, which is **the one place a utility is applied** (`episode.md` §3, `reward.md` §1, D-20), and the run's `shape`, so its chips-in-play guard reads that shape's own total — 40 on the default shape, 200 on `no-limit-100` and 600 on `six-seat-no-limit-100` (`episode.md` §3, `reward.md` §4, `shapes.md` §2, §8, D-29). **Every transition carries the episode's own seed** and a resolved hand's transitions carry the counterfactual member's values, the two facts D-43 puts in the transition record and the members of the third catalogue read (`episode.md` §3, `counterfactual.md` §2, §4, D-43). Its `td_error` is the hand's learning signal (`curves.md` §3). **A hand in which the learner's seat never acted produces no batch and no update** — `learn` refuses an empty sequence — and contributes no signal (`agents/rule.md` §3).
7. **Snapshot every interval.** After hand *i* with `(i + 1) % interval == 0`, and at most ten times, the run makes the pair's directory and calls `agents.save(learner, layout._write_path(layout._snapshot_path(...)))`, keeping the path it returns (`checkpoints.md` §2, `write-root.md` §1, §5). The interval is `budget // 10`; §2 says why it is not the declared `snapshot_every`.
8. **Write the final model, then play the pass.** After the last hand, `agents.save(learner, layout._write_path(layout._final_path(...)))` writes `final.ckpt` for that pair (`checkpoints.md` §2, ASM-18), and the pair's curve closes with the spread across seeds (`curves.md` §4); the helper names the *declared* layout, `_write_path` re-roots it and `layout._relative` spells it (`write-root.md` §2, §5, §6). With the model on disk — so the block is reproducible from the checkpoint the record names — the run then plays the pair's **greedy pass**: `greedy._pass(pool, shape, seed, greedy._sample(budget), agents.as_policy(learner, encoder, int(seed), "off"), where)`, the one decision stream a run retains, played over the run's own **first `min(budget, 2,000)` hands** and writing nothing (`greedy.md` §1–§4, `sizing.md` §4, `records.md` §15, ASM-38, D-28, D-36).
9. **Assemble the record.** `_record(...)` returns §3's mapping — `record.md` §1's keys — and nothing beyond it, the run's `game` and the per-variant, per-seed `greedy` block included: a run claims no table position and fits no rating (`module-map.md` §3, `records.md` §12, §13, §15, `record.md` §1, §3, `surface.md` §4, D-29). **The layout is the same on every shape, and what a six-seat run cannot write is a table.** A run on `six-seat-no-limit-100` writes the curves, the pool, its ten snapshots, its final model and its `greedy` block, and its record names the six-seat shape at the top level, in the pool's `game` and in the header's `game` and six-descriptor `action space`; what it has no position in is a matrix, because `evaluation.match`, `matrix`, `rating` and `report` refuse a shape whose seat count is not two — a cell is a pair and a six-way hand is a placement — so a six-seat run has no table position and no report, and this module computes neither on any shape (`seats.md` §5, `records.md` §12, `record.md` §3, `module-map.md` §3, D-33).

**The nine steps are the same for R1 and for a configuration in no registry**; only the data differs, and that is the whole of D-3 (`ladder.md` §1, FAM-15, FAM-16.29). No step is conditional on a rung name, a rule, a utility **or a shape**, because all four are declarations a configuration carries and the shape is forwarded as data — that is the whole of D-29's "the shape is data all the way down" (`rules.md` §4, `utilities.md` §5, `shapes.md` §1–§2, D-19, D-20, D-29).

## 2. One variant × one seed: `_train_variant_seed`

`_train_variant_seed(config, entry, seed, budget, device, pool=None, shape=None) -> (curve, checkpoints, timing, greedy_block)` runs steps 3–8 and the pass step 8 ends with, and returns **four** plain records; it is the only place a learner exists (`loop.py`, `README.md` §4). Three rules of its own:

- **The interval is `budget // 10`, not the declared `snapshot_every`.** ASM-18 fixes ten equally spaced snapshots, and a run's budget is not the configuration's declared one: the battery runs 60 and 250 hands (`battery.md` §2). At 250 hands a declared 100 would write two snapshots and leave FAM-12.4's five-version window unobservable; at `budget // 10` it writes exactly ten, the last at `10 × interval ≤ budget` (`curves.md` §2). The declared value is **recorded**, in §4's `variants` row.
- **The pass is sequential and single-threaded**: one hand at a time, because one global `random` stream deals every hand and concurrency is not available (`protocol.md` §4, ASM-2). No hand is buffered, replayed or reordered.
- **The timing is measured, not asserted**: `_timings(start, hands)` reads `time.perf_counter()` around the pair's hands and returns §4's four facts; a run never claims a wall clock was beaten (`records.md` §12, ASM-15, FAM-13.5).

**The shape is threaded, never branched on.** `shape` is resolved once at step 1 and passed down, so every derivation the loop makes from the game is the run's own and never `engine.game_config()`'s default: the encoder's spec, the learner's head width, the seat count and rotation `episode._seats`/`_seat` read, the hand's seating, the policy's decode and the transition step's guard (`policies.py`, `episode.py` §1, `shapes.md` §2, §8, `sizing.md` §5–§6, `seats.md` §4, D-29, D-33). A `_train_variant_seed` and a `_pool` called with no shape resolve it from the configuration they were handed, so a unit case may pass one argument fewer and no path ever falls back to the default shape silently (`README.md` §4, D-13).

**The pass comes last, and it is the only decision stream a run retains.** Once the pair's final model is written, `greedy._pass` replays the pair's sample — its first `greedy._sample(budget)` hands, `min(budget, 2,000)` — against `agents.as_policy` at `exploration="off"` and returns `records.md` §15's block (`greedy.md` §1, §4, `sizing.md` §4, ASM-38, D-36). Running it after the save is what makes the block reproducible from the record; the training decisions themselves are never retained (D-28), and the block is a function of the tuple this section's three rules already fix (`greedy.md` §5).

**All three axes are resolved one way, and none is substituted.** `_declared_rule` and `_declared_utility` read the entry's declaration first, its configuration's second — a level declaring none, or `None`, is no claim and they return `None` — and `_trained_rule` and `_trained_utility` fall back to the **catalogue's first** member of their axis, through `declarations.learning_rules()` and `declarations.utilities()`, so a variant naming neither is trained under `masked-q-learning` on `net-chips` (`rules.md` §4, `utilities.md` §5, D-19, D-20). The shape resolves the same way through `_declared(configuration, "game")` and `declarations.require_game`, except that absence is the **default shape** and never "no claim", because a shape is a property of the configuration and not an optional member (§1 step 1, `shapes.md` §3, D-29).

**The third axis is resolved the same way and recorded on a stricter condition.** `_declared_counterfactual` reads the entry's `counterfactual` and then its configuration's on the terms above, and `_trained_counterfactual` falls back to the **catalogue's first** member through `declarations.counterfactuals()` — `none`, the rule's own bootstrap target — so a variant naming none is trained exactly as before (`counterfactual.md` §6, D-43). What differs is **where the member is written down**: the spec carries the key only when the declaration was made, and the run records it only when the resolved member is **not** the catalogue's first — one line of it in the variant's `variants` row and one entry in the run's `counterfactuals` set, a set that is written only if it is not empty. That conditionality is the whole of D-43's "no shipped artefact moves": a default declaration's record and container are the ones they always were (`counterfactual.md` §6, §9, `records.md` §12, §4).

**The declaration a run would discard is refused; a catalogued member is not (Rev 4, Rev 7, Rev 9, Rev 13).** At §1 step 1 a `learning_rule`, a `utility` or a `counterfactual` the catalogue `agents.learners()` publishes does not carry is `IgnoredDeclaration` — named with the other two axes and naming every member the catalogue carries — as a `game` the catalogue `engine.game_shapes()` publishes does not carry is `UnknownShape` — its own class, naming the level, the name and every declared name — as a `hyper` key whose value is not that key's `declarations.HYPER` value (an unknown key included) and a `snapshot_every` that is not the **declared** samples ÷ 10 is, each at the configuration and at each entry, and both levels are named. Two arms declaring two values for one of the **six** settings that reach the pair check are `PairDeclarationsDiffer`, naming the key and both values; a catalogued rule, utility or counterfactual is not one of them, so two arms may declare two of any of them and both are trained, while a `game` **is** one of them, because two arms of a pair are trained and evaluated on one shape and a shape is never a rung's axis (D-19, D-20, D-43, `rules.md` §8, `utilities.md` §8, `counterfactual.md` §6, §9, `shapes.md` §1, §6, `ladder.md` §4, D-29). A `param_budget` that is not a positive integer is `VariantSettingInvalid`; an absent setting — or one spelled `None` — is no claim, and a `hyper` that is not a mapping names no key (`declarations.md` §2–§4, ASM-7, ASM-10, ASM-18).
**The comparison is by declaration, never by structural equality.** `seeds` compares as a sequence, and two `hyper` blocks differ when a key **both** name carries two values; with those two checks above, the pair check covers `samples`, `seeds`, `device`, `table`, `param_budget` and `game` (`declarations.md` §4).

Every write in the pass goes through `os.makedirs(parent, exist_ok=True)` before `agents.save`, because `save` invents no directory and refuses a path whose parent is missing (`agents/surface.md` §8, `checkpoints.md` §2). The parent is made **under the write root**, `layout._write_root()` — `CHECKPOINT_ROOT` unless the ambient `PYPOKER_CHECKPOINT_ROOT` names another root — and both artefacts reach `save` through `layout._write_path`, so a battery's run writes a temporary tree and the shipped one is untouched (`write-root.md` §6). The **pass** writes nothing at all: it has no path, no directory and no artefact, and the record's `checkpoints` block is the one the save produced (`greedy.md` §1, `record.md` §2).

## 3. The run record, key by key (D3)

`records.md` §12's fifteen **required** keys — thirteen before D-29, which adds `game` and `greedy` — then this module's own evidence keys, `header`, `baselines` and `axis row` (`surface.md` §4, `records.md` §12, §15, `utilities.md` §7, D-29). **The table that fixes each key, key by key, is `record.md` §1**, moved there whole at Rev 9, when this file was at its 190-line ceiling; the split keeps §3's number, which `tests/training/test_loop.py` cites, and it is a pointer and not a second claim.

**One id per record, and it is the declared one** (D3): `pool.id` is `config["pool"]["id"]` — for a registry rung the read-back id of the membership, for a custom configuration its own `"pool-r7"`-style id — and the read-back digest id is **not** carried anywhere in the record, because `tests/e2e/_surface.py`'s `pool_identity` reads every `id` a record declares and two ids in one two-variant record fail FAM-3.18 (ASM-16).

**And the two keys D-29 adds are as plain as the rest.** `game` names the single shape the run played, so a record never names a shape it did not measure; `greedy` is one block per variant per seed, keyed exactly as `curves` is, and is the **only** decision log in the record (`record.md` §3, `greedy.md` §2–§3, `sizing.md` §4, D-28, D-29).

## 4. The sub-records, in the shape their readers expect

Each sub-record is fixed in `record.md` §2, moved there whole at Rev 9; its shape, in one line each:

- `curves[V][str(seed)]` — three ten-element lists: the axis, the signal and the across-seed spread, repeated at each of that variant's seeds because it is one fact about it (`curves.md` §5).
- `checkpoints[V][str(seed)]` — `{snapshots: [the retained five], final: <one path>}`: six artefacts per pair and never eleven, and the pass adds no seventh (`checkpoints.md` §3, `write-root.md` §5, `greedy.md` §1).
- `params[V]` — the declared budget and its ∓2% band, declared and never measured (`module-map.md` §2, ASM-10).
- `timings[V][str(seed)]` — the four facts `harness.timings` reports; the key names are deliberate, because the battery's `timing_facts` classifies a key by what it names (`e2e-surface.md` §3.6, ASM-15, FAM-13.5).
- `variants[i]` — the entry's declaration plus **the rule and the utility the learner was actually built under**, and the interval the run used (`rules.md` §4, `utilities.md` §5, D-19, D-20).
- `rules` and `utilities` — the two sets the per-variant rows name, deduped in declaration order; `pool.rules` and `pool.utilities` are the same sets for the opposition (`records.md` §8, §12, D-19, D-20).
- `baselines` and `header` — one row per baseline the pool holds with its declared `0`, and a header whose `game` and `action space` rows are the run's **shape's** (`record.md` §3, ASM-32, D-21, D-29).

## 5. The arguments, and what an omitted one means (D3)

`run(rung, seeds=None, budget=None, device=None)` (`surface.md` §4):

- `seeds` omitted → the configuration's own `seeds`, else its first variant entry's `seeds`; a configuration carrying neither is `MissingConfigurationKey` naming `seeds`, and no seed set is substituted for an absent one (§6, `e2e-surface.md` §2, D-12).
- `budget` omitted → the configuration's `samples`, else its first variant entry's `samples`, else `LIVE_BUDGET` is **not**
  substituted: a configuration carrying none is refused naming `samples` (`e2e-surface.md` §2, D-12).
- `device` omitted → the configuration's `device`, else `devices()["default"]`, which is `"cpu"`; a named device must be one
  `devices()["available"]` lists, or the run refuses naming it (`devices.md` §1, D-8).
- `game` is **not** an argument: it is the configuration's own key, read at the configuration then at its first entry, and its absence is the catalogue's first shape — so the shape reaches a run only as a declaration and never as a caller's option (`surface.md` §4, `shapes.md` §3, D-29).
- `snapshot_every`, `table` and the pool's `baselines` are read from the configuration and are never arguments: the interval is `budget // 10` (§2), a missing `table` is recorded as `live`, and `learning_rule`, `utility` and `game` are read from the declaration too (`utilities.md` §5, D-20, D-21, D-29).

## 6. The refusals of this document

This module's own refusals raise a `TrainingError` subclass naming the offending value (`errors.md` §2–§4), before the first hand is
dealt and before anything is written; the two rows marked *the owner's class* and *the pool's own class* propagate unchanged (`e2e-surface.md` §2).

| Refusal | When |
|---|---|
| `UnknownRung` | `rung` is a string `RUNG_NAMES` does not carry — named (`registry.md` §5, FAM-15.5) |
| `ConfigurationInvalid` | a configuration missing a key the run reads, or one that is not a mapping — the key is named (§1, §5) |
| `VariantCountInvalid` | `variants` holds zero, three or more entries; one or two only (`ladder.md` §2, `surface.md` §4) |
| `VariantSettingInvalid` | a setting the run reads has the wrong shape: `backend` or `encoding` is not a string, `architecture` is not a mapping, `width`/`depth` is not a positive integer, `sparsity` is outside `[0, 1]`, or a declared `param_budget` — at the configuration or at an entry — is not a positive integer — the field, its level and its value are named (`records.md` §2, `ladder.md` §3, ASM-10) |
| *(the owner's class)* | a `backend`, an `encoding`, an `architecture.kind`, a `learning_rule` or a `utility` the owning module does not declare is refused by **that** module, at §1 step 3: `features.build_encoder` for the encoding and `agents.build_learner` for the backend, the kind, the rule and the utility, whose message names the value; this module reads no such catalogue except the two `learners()` publishes, and re-wraps none (`module-map.md` §2, `features/surface.md` §4, `agents/surface.md` §4, D-20) |
| `MissingConfigurationKey` | a configuration carrying none of the places §5 looks for `seeds` or `samples` — the key is named, and no value is substituted for an absent one. `device` is not among them: an omitted device resolves to `devices()`'s declared default (§5, D-8) |
| `InvalidSeeds` | the seed set is empty, repeats a seed, or holds a non-integer (ASM-2, `surface.md` §4) |
| `InvalidBudget` | `budget` is not a positive integer, or is below ten hands — ten equally spaced snapshots need ten hands (`surface.md` §4, ASM-18) |

| `IgnoredDeclaration` | a declaration the run would not use, raised after every shape check above and before the pool: a `learning_rule`, a `utility` or a `counterfactual` the catalogue `agents.learners()` publishes does not carry, a `hyper` key whose value is not that key's `declarations.HYPER` value (an unknown key included), and a `snapshot_every` at either level that is not the **declared** samples ÷ 10 — each **at the configuration and at each entry**, naming the level, the key, the member or value declared and the catalogue or value the run uses (`declarations.md` §2–§3, `rules.md` §2, `utilities.md` §2, `counterfactual.md` §6, D-19, D-20, D-43, ASM-18) |
| `PairDeclarationsDiffer` | a two-entry configuration whose arms declare two values for one of `samples`, `seeds`, `device`, `table`, `param_budget` or `game` — **six** of the eight settings a pair shares, because `hyper` and `snapshot_every` are refused earlier and per arm by `IgnoredDeclaration` and the pair class is unreachable for them: two arms cannot differ on a `hyper` value or an interval without one arm disagreeing with the declaration in force, and the `hyper`, member and interval checks run before the pair check — a key only one arm declares is no claim, and the message names the key and both values. `game` is one of the six because a pair is trained and evaluated on **one shape** and a shape is never a rung's axis; `learning_rule` and `utility` are **not** among them, since two arms may declare two of either, which are the pair's `rule` and `utility` axes (`declarations.md` §2, §4, `rules.md` §8, `utilities.md` §8, `shapes.md` §1, §6, `ladder.md` §4, ASM-8, ASM-16, D-29) |
| `GreedyPassRefused` | the pass's own two bounds, and **never a run's budget**: `_check_hands` refuses a **pass request** above 2,000 hands per variant per seed, naming the count the pass was asked for and the bound — the loop asks for `greedy._sample(budget)`, which is at most the bound, so no budget reaches it from `run` (D-36); a request that is **not a positive integer** — a `bool`, a float, a string, 0 or a negative — is refused by that same seam before a hand is dealt, naming the request as given and the contract `at least 1 hand and at most 2,000`; or, as the pass accumulates, the moment one more decision record would cross the **run's own shape's** record bound, `declarations.greedy_decisions(shape)` — 24,000 at the default shape, 66,000 and 98,000 on the uncapped ones — named with the count, the bound, the shape and its history capacity; never truncated, and a pass of exactly a bound is inside it (`greedy.md` §4, `errors.md` §4, `sizing.md` §4, `records.md` §15, `shapes.md` §8, ASM-38, ASM-42, D-33, D-36) |

## 7. Determinism

One `(configuration, seed set, budget, pool membership)` gives one record twice: the same curves, the same pool id, the same
checkpoint paths, the same rules and utilities, and the same `greedy` block (`surface.md` §4, FAM-4.7, `greedy.md` §5, ASM-38), because each variant's rule, utility, counterfactual member and shape are declarations and not draws. Four facts carry it: the deal and opponent seeds are derivations of `(seed, i)` (`seeds.md` §2), the learner's generator is seeded from the run seed (`agents/architecture.md` §4), the pool is frozen before the first hand so the opponent draw depends on the membership alone (`registry.md` §3, ASM-16), and the pass draws from no generator at all, because its mode is `off` (`greedy.md` §1, §5, `docs/L3/agents/rule.md` §4). A different seed set gives different curves (FAM-4.8), a different membership a different pool id (FAM-4.9); the **timings** are the one field two runs of one tuple differ in (`surface.md` §4). The block's guarantee is the record's and no wider: within one process, because the training path itself is hash-order sensitive across processes (`greedy.md` §5).
