## 1. What this module is

`training` **is** the rung registry plus the one training loop every rung is a configuration of (D-3): it declares the lineage it inherits, freezes the pool that lineage yields before a variant trains — the catalogue's pinned baselines plus whatever `baselines` names it declares — draws each hand's opponent from that pool, plays through `engine` on an observation from `features` and a decision and update from `agents`, builds each variant under the rule, the utility and the **shape** it declares, and returns the run record (`module-map.md` §1, §3, D-16, D-19, D-20, D-21, D-29). It claims no result, measures no cell, fits no rating and never chooses the membership (D-16, ASM-16, ASM-32), so a rung-to-rung difference belongs to the configuration and a seventh configuration runs without new code (D-3, FAM-15). Its other two owned paths are data — `notebooks/`, one thin notebook per rung calling declared entry points only (D-5, `ladder.md` §7), and `checkpoints/`, the shipped models and the intra-run snapshots the pool is a view over (ASM-18).

**And it retains exactly one decision stream.** A run discards its training decisions — a log of them would be a log of the exploration schedule, the defect D-28 records as fatal — and ends each variant's pass at a seed with an exploration-off **greedy pass** over its own sample, recorded under the record's `greedy` block (`sizing.md` §4, `records.md` §15, ASM-38, `greedy.md` §1–§3). The shape is a declaration all the way down: it is read once, forwarded to every call that derives something from the game, and reported by the record and by `fairness` (`shapes.md` §1–§3, D-29). **A shape whose seat count is not two trains and passes as any other and has no table position**: `evaluation.match`, `matrix`, `rating` and `report` refuse it, because a cell is a pair and a six-way hand is a placement, so a six-seat run writes the same record and no matrix, and this module measures no cell on any shape (`seats.md` §5, `records.md` §12, D-33).

## 3. The six names

`src/training/__init__.py` exports exactly the six entry points of `e2e-surface.md` §3.5 in that order, declares them in `__all__`, and adds, removes and renames none (D-12):

    rungs()                                          -> Mapping  # the six resolved configurations, brief §2's order
    rung(name)                                       -> Mapping  # one resolved configuration, or UnknownRung
    run(rung, seeds=None, budget=None, device=None)  -> Mapping  # records.md §12's record — `game`, `greedy`, `variants`, `rules`, `utilities` among its keys
    fairness(left, right)                            -> Mapping  # {pair, axis, constants, pool}
    devices()                                        -> Mapping  # {available, default, gpu}
    checkpoints()                                    -> Mapping  # {entries, shipped}

`RUNGS`, `HYPER`, `SHAPE_NAMES`, `DEFAULT_SHAPE`, `SHAPE_ACTIONS`, `SHAPE_HISTORY`, `GREEDY_HANDS`, `GREEDY_DECISIONS_PER_SLOT`, `_Curve`, `TrainingError` and its subclasses and every `_`-name stay below an entry point and are **not** surface (`surface.md` §1); no returned record exposes a learner, an encoder, a policy or a pool (D-1). `game` is not a seventh argument: the shape is the configuration's own key (`loop.md` §5, `shapes.md` §3, D-29), and no seat count is a declaration of this module's — `2` and `6` are `engine.game_config`'s (`seats.md` §2–§3, ASM-44).

## 5. The import boundary (D10)

`training` imports the standard library (`collections.abc`, `copy`, `errno`, `hashlib`, `os`, `statistics`, `time`) and exactly the granted calls (`module-map.md` §2, `docs/L2/training/surface.md` §1, D-13):

    evaluation  protocol, league, build_pool, pool_members, opponent  — never match, matrix, rating, report, offer, policy_from
    agents      learners, build_learner, act, learn, save             — never load, param_count, baselines
                as_policy(learner, encoder, seed, "off")              — the pass's policy and nothing else's
    features    build_encoder, encode, observation_spec, legal_indices, decode_action  — never encodings(), action_space()
    engine      game_config, new_hand, play_hand, payoffs             — never readout, legal_actions, apply_action, is_terminal

**`agents.as_policy` is a sixth `agents` call, and it is the pass's alone.** The training-time decision is still the policy assembled here from `features.encode` + `features.legal_indices` + `agents.act` + `features.decode_action` (`episode.md` §2), because the module needs a decision that keeps no log and returns an index; the exploration-off pass is the one place a callable policy is wanted, and `agents.as_policy` at `exploration="off"` is what plays it (`greedy.md` §1, `sizing.md` §4, ASM-38). `docs/L2/training/surface.md` §1 grants it on exactly that term; `module-map.md` §2's `training` → `agents` row still lists five and does not carry it, and that row is L1's to re-issue — this revision states the call this module makes and does not edit the map (D-13).

`declarations.BASELINES` is `evaluation.league()`'s `baselines` — the catalogue's `anchor: True` set, in the catalogue's order — so the pinned set is never a literal, no `baselines` call is added to the boundary, and a folder joins a pool only when a `pool` entry names it (`folders.md` §4, ASM-32, D-21). Never `harness`, never `pokerkit`, and no numerical library at module scope: the one conditional import in the module is `devices.py`'s backend probe, which imports `torch` **only after** a **read-write** open of a GPU device node has succeeded, once per process, and reports the operation, the errno and the platform situation the backend's own refusal leaves it in (`devices.md` §2, Rev 3, measured). `statistics` serves the curve (`curves.md` §3), and no call here seeds or advances the global `random` stream; only dealing moves it, and at or below the pass's hand bound the pass's last deal is the one training ended on, so there a run leaves the stream where its training left it — above the bound the pass stops at hand `S − 1` (`greedy.md` §5, D-36).

## 6. Facts inherited from the four modules this one calls

- `engine.play_hand(seed, seat0, seat1, shape=None, seats=None)` deals at that seed and returns `records.md` §5's episode record; seat 0 holds the button in **every** hand, so a two-seat hand is the two positional policies swapped hand by hand while a hand of a shape with more seats is played from one `seats` sequence, one policy per seat in seat order, the two forms being exclusive; `evaluation.opponent(pool, seed, count=None)` draws one member, or `count` **distinct** members without replacement in the draw's order and refuses a pool holding fewer of them; the `shape` is the run's own and a hand played on it conserves that shape's chips in play (`engine/surface.md` §4, §10, ASM-12, `e2e-surface.md` §3.1, §3.4, `shapes.md` §2, `seats.md` §2, §4, ASM-43, D-29, D-33, `league.md` §3).
- `features.legal_indices` is **position-aligned** with its argument, so a chosen descriptor becomes its vocabulary index by position and no second legality channel is invented; `features.decode_action(index, shape=...)` answers that shape's descriptor for an index, three on the default shape and six on either uncapped one; `agents.act` returns a mapping whose `action` is the chosen index; `agents.learn` consumes the caller's order, returns `td_error` and reads the reward it is handed, whatever utility produced it; `agents.save` writes exactly the path given and invents no directory; `agents.as_policy(learner, encoder, seed, "off")` returns the masked-maximum policy the pass plays, drawing from no generator (`agents/surface.md` §6, §7, `features/surface.md` §8–§9, `e2e-surface.md` §3.3, ASM-38).
- `evaluation.build_pool` freezes one declaration — a `pool` entry's `baselines` forwarded as it stands, and the run's `game` with it, because a pool is one shape's — and `pool_members` reads back `id`, `m`, `frozen`, `game` and the pinned baselines, the anchor three and any declared folder (`evaluation/pool.md` §1–§2, ASM-32, D-21, `records.md` §8, D-29).

## 7. The decisions this design fixed, each with the alternative it rejected

| # | Decision | Why | Rejected alternative |
|---|---|---|---|
| 1 | the six rows are one literal table in `declarations.py` (registry.md §1) | a rung is data, so no rung drifts into a copy of the loop (D-3, FAM-15) | a function per rung, which is six loops under one name |
| 2 | the snapshot interval is `budget // 10` at the budget the run was given (loop.md §2) | ASM-18 wants ten equally spaced snapshots at **any** budget, and the battery runs 60 and 250 | the declared `snapshot_every`, which yields two snapshots at 250 hands (FAM-12.4) |
| 3 | deal and opponent seeds are a `sha256` derivation of `(seed, hand index)` (seeds.md §2) | both arms must play the same hands, and no stream may be drawn on (ASM-2, ASM-16) | `seed + i`, which correlates adjacent hands and collides across rungs |
| 4 | the training-time side is a policy assembled from `encode`/`legal_indices`/`act`/`decode_action`, and the pass's is `agents.as_policy` at `exploration="off"` (episode.md §2, greedy.md §1) | the loop needs an index and no log, and a census needs a greedy policy with no generator (`sizing.md` §4, D-19, D-28, ASM-38) | `agents.as_policy` for training, which records nothing and returns a descriptor; and the ε = 0.05 tail as "nearly greedy" (`greedy.md` §3) |
| 5 | the run record's `pool.id` is the **declared** id; the read-back digest is never carried (loop.md §3) | one id per record proves both arms held one pool (FAM-3.18, ASM-16) | carrying both, which makes a record declare two pools |
| 6 | the index is declared data in `index.py`, one listing per artefact (checkpoints.md §4) | never a directory scan, so a scratch file is not a shipped artefact (FAM-16.31) | `os.walk`, which lists the battery's own scratch files |
| 7 | `fairness` compares `architecture` only when family and `sparsity` agree (fairness.md §2) | a capacity match is the *compensation* for another axis (ASM-10) | comparing width always, which refuses R5's pair on two axes (FAM-3.12) |
| 8 | a path is **written** absolute — `_write_path` of a declared path, under the write root — and **recorded** repository-relative with POSIX separators when the artefact is inside the repository root, **unchanged (absolute)** when it is outside, then read back through `layout._resolve` from the repository root (checkpoints.md §2, write-root.md §5) | a record stays portable without pretending an outside artefact ships, and a redirected run's record still names a file that exists (protocol.md §5, D-8) | absolute paths for inside artefacts, which is what the shipped evidence bundle first carried, so nothing but the machine that made it could read it |
| 9 | the write root is one **ambient** override, `PYPOKER_CHECKPOINT_ROOT`, which `layout._write_root()` reads on every call and never caches (checkpoints.md §1–§2) | one fact reaches every caller that must be pointed elsewhere — a pytest session, a shell, a notebook kernel — and the module learns no second argument (write-root.md §3, D-13) | a `root` keyword on `run`, or a seventh exported setter: the first is a signature change and the second a new entry point, so either is an `ADJUDICATION` to L1 and never L2's to invent (write-root.md §3, D-12) |
| 10 | a variant's `learning_rule` is **read and forwarded** into `agents.build_learner`'s spec, and the catalogue is read through `agents.learners()` (loop.md §1 step 3, guardrails G23) | D-19 makes the estimator a parameter, so the run builds the rule the entry names and refuses only a name the catalogue does not carry (rules.md §2, §4, D-19) | a module constant the run holds, which is ASM-7's retired single-rule clause: a second rule would then be a declaration the run discards |
| 11 | the terminal reward is re-expressed by the variant's utility **in the transition step**, selected by the catalogue's reward token and never by a member name copied into this module (reward.md §1–§2) | D-20 puts the reward where the completed hand's stacks are, and `agents.learn`'s terminal branch stays `target = record["reward"]` (`utilities.md` §4, ASM-28, D-20) | the transform inside `learn`'s terminal branch, which would put the reward definition and the TD bootstrap in one arithmetic (D-19, D-20) |
| 12 | the shape is **data**: one name resolved once, forwarded to the encoder, the learner's head, the seat count, the seating, the policy's decode, the transition guard, the pool and the header, and refused only when it is not a declared name (loop.md §1, episode.md §1, `shapes.md` §1–§2) | D-29 and D-33 declare three shapes and a shape is not a rung, so every derivation must follow the declaration, no call may fall back to the engine's default, and no seat count may be written down (`sizing.md` §5–§6, `seats.md` §2–§4, ASM-44, D-29, D-33) | a `game` argument on `run`, a literal seat count beside the shape, or a per-shape branch per step: the first is a seventh argument and a signature change, the second a second declaration of the game, the third puts the game in the loop instead of the data (`shapes.md` §1, D-12) |

## 8. Decisions a later module must not re-derive

1. **A rung is a row of data and `run` is the only path into the loop**; `rung(name)` never resolves a configuration (D-3).
2. **The interval is `budget // 10`, and every seed is a `hashlib` derivation of `(seed, index)` and never a draw** (seeds.md §2).
3. **A transition's `action` is an index, a terminal transition carries its own `next_legal`, and the terminal reward is the utility's** — `0.0` elsewhere, and no arithmetic in `learner.py` reads a utility (episode.md §3–§4, reward.md §1, §5, D-20).
4. **The record names the retained five and the final model, carries one pool id — the declared one — states each variant's rule and utility plus the run's `rules` and `utilities` sets, and names the one shape it played** (loop.md §3, record.md §1, §3, D-19, D-20, D-29); **a pool's pinned set is the catalogue's `anchor: True` members read off the flag plus the folders a declaration's `baselines` names, and no count here is a hard-coded three** (registry.md §3, loop.md §4, fairness.md §5, ASM-32, D-21).
