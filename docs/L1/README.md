## What changed at Rev 2, Rev 3, Rev 4, Rev 5, Rev 6, Rev 7 and Rev 8

D-16 replaced D-6's head-to-head opponent with a bounded round-robin league — the model's last M versions plus the three fixed baselines — as both training and evaluation opposition (Rev 2): `league.md` owns the pool, scheduler, matrix, rating and tables, and `e2e-surface.md` replaces `evaluation.head_to_head` with the league's entry points, 11 `evaluation` endpoints and 49 across the map. Rev 3 and Rev 4 repair the two blind walkthroughs (`strata/records/phase1-walkthrough.md`): the matrix is separated from the rating and a rank asserts no head-to-head win (`league.md` §3.1, §8), the measured per-hand cost and the live table's higher own figure replace ASM-15's 40 ms bound (`league.md` §7, ASM-21), `battery.md` §2 gives the supported way to run the batteries and says where they write, `ladder.md` §7 says which notebook ships and that it finds the repository root itself, `getting-started.md` is the newcomer route and warns where a run writes, `records.md` §9 states what a recorded cell seed reproduces, `protocol.md` §4 records that reproducibility is one build's and one pinned interpreter's, and the evidence bundle names its own build (`protocol.md` §5). Rev 5 adds `gpu.md`, which D-17 requires: the measurement that a delegated agent cannot reach the GPU, the code being CPU-only regardless, the commands a user runs in their own shell to verify the card, and the device rule that keeps a CPU figure and a GPU figure apart.

Rev 6 closes the four findings of an earlier pass, recorded in `strata/records/phase1-walkthrough.md`: the band the brief's ASM-21 amendment fixes, the missing PyTorch figure, the notebook rewriting the shipped set, and the checkpoint seed/encoding rule no layer had written. `league.md` §7 and `assumptions.md`'s ASM-15 quote the band and the projections the brief's ASM-21 states after L0 amended it — 0.105–0.153 s/hand, ≈95–110 s at K = 4, ≈10–12 minutes at K = 9–10 and ≈2 hours full — and that band is carried down to `docs/L2/evaluation/league.md` §5, `docs/L3/evaluation/tables.md` §1/§6 and `docs/L3/evaluation/declarations.md` §4.1 by those layers, so no layer below this one quotes an older figure. `gpu.md` §5 states the measured R1/R2 speed-up (0.1111 → 0.0451 s/hand, 2.46×, recorded in `strata/records/r2-speed.md`) in place of claiming that no PyTorch figure exists. And `ladder.md` §7 records that the R1 notebook's run writes 33 paths, of which the 18 the repository ships are exactly the shipped set's — which is how that notebook came to overwrite them — and that the notebook now writes to `/tmp/pypoker-notebook-r1` by default (`PYPOKER_CHECKPOINT_ROOT` redirects it) and says so in its opening markdown. `assumptions.md` gains ASM-20 — a checkpoint records the seed and the encoding a member is built at, so `policy_from(path)` reads exactly those two facts and no seed is ever substituted — a rule three downstream documents and the module itself already cited and no layer had written.

Rev 7 closes L1's two findings of the pass after Rev 6's — the **write-root** finding, where an `unittest` census passed its cases and still left 164 files under `checkpoints/`, and the **one-build's-seconds** finding, where four documents quoted a superseded generation — both recorded in `strata/records/phase1-walkthrough.md`. The write-root isolation is now established by **whichever hook the runner loads** — `tests/conftest.py` under `pytest`, `tests/e2e/__init__.py` under the `unittest` census, which loads no conftest at all — so both documented runners leave `checkpoints/` untouched; `battery.md` §2 and `getting-started.md` §6 say so, and the same mechanism is carried down through `docs/L3/harness/layout.md` §5, `docs/L2/training/write-root.md` §4 and the census line of `docs/L3/evaluation/guardrails.md` G22. And `league.md` §7, `assumptions.md`'s ASM-15, `protocol.md` §5 and `gpu.md` §1/§5 stop quoting one build's seconds: they state the measured **band** and the per-artefact **shape** and point at `checkpoints/evidence/r1-live.json` and `tables/league-full.json` for the current values, because every regeneration moves them — a document that describes one artefact's own contents still quotes it exactly, and only as that generation: `docs/L3/training/evidence.md` §3 is synced to the bundle's commit and `generated_utc`, so a reader compares the file rather than trusting the prose. The band does not move: 0.105–0.153 s/hand, ≈95–110 s at K = 4, ≈10–12 minutes at K = 9–10 and ≈2 hours full (ASM-21).

Rev 8 closes the three findings that were left, and all three are bookkeeping: `docs/L3/training/evidence.md` §2's `devices` row stops calling the bundle's `gpu.reason` a superseded read-only probe's sentence, because the regenerated bundle carries today's **read-write** sentence — byte-identical to `training.devices()['gpu']['reason']` on this platform, which is `docs/L3/training/devices.md` §2's sandbox-denial text; every citation that named a finding by a number and a run names its **subject** instead (`docs/L3/harness/layout.md` §5, `docs/L3/training/checkpoints.md` §5, `docs/L2/training/write-root.md` §4, `league.md` §3.1, `gpu.md` §5, `assumptions.md` and this page), and the rule is stated below (D-14, ASM-22); and the two artefact sets are told apart wherever they are counted — a run **writes** 33 paths for three seeds (ten snapshots and a final per variant × seed) and the repository **ships** 18 (the retained window's last five per seed plus each seed's final) — with `protocol.md` §5, `ladder.md` §7, `getting-started.md` §4, `module-map.md` §5, the R1 notebook's opening markdown and `docs/L3/training/checkpoints.md` §5 saying it one way, which is exactly what `training.checkpoints()`'s 18 entries and `checkpoints/`'s 18 `.ckpt` files hold (ASM-18, `checkpoints/evidence/r1-live.json`).

## Reading order

| Document | What it answers |
|---|---|
| `getting-started.md` | the route in: Python, dependencies, `PYTHONPATH=src`, one training run, one league table |
| `gpu.md` | what runs on CPU today, why an agent cannot run the GPU path, and the commands a user runs to verify the card and measure the PyTorch-versus-NumPy difference (D-17, D-7, D-8) |
| `module-map.md` | the six modules, the league's owner, their interactions, path ownership, and the harness contract of brief §5 |
| `e2e-surface.md` | every entry point the battery drives, the shared contracts behind them, the endpoint counts in `modules.json`, and which surfaces are general-purpose |
| `records.md` | the mapping shape each entry point exchanges, the league's pool, cell, matrix and rating records included, so no module reads another's type (D-13) |
| `ladder.md` | the six rungs as configurations of one machinery, what a comparison holds constant, the budgets, and where the D-5 notebooks live |
| `protocol.md` | the evidence a rung must report (D-6, D-16), the three fixed baselines (ASM-4), the seed contract (ASM-2), checkpoint retention (ASM-5, D-16), and the device rule (D-8) |

| `assumptions.md` | what L1 decided where the brief left the answer here, each with the alternative it rejected |

The game is heads-up fixed-limit Hold'em (D-2), the ladder's order is brief §2's (D-3), and the league is D-16; Phase 2 is not designed here (D-4, D-9). **A citation names a subject, never a number**: a document cites "the write-root finding in `strata/records/phase1-walkthrough.md`" or
"the notebook-in-place-rewrite finding", and never "finding n of run k", because that record is replaced on every run (§7 of `strata/walkthrough.md`, D-14, ASM-22).
