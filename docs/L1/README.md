Rev 11 closes the three items the engine's L3 split exposed and writes the one rule it had left implicit. `docs/L3/engine/errors.md` passed its 70-line ceiling and is split at its own owner boundary: the message grammar and the canonical message per refusal move whole to `docs/L3/engine/messages.md` §1, `docs/L3/engine/errors.md` §3 stays as the redirect that keeps its number resolving, and the engine's documents are one per owner again (`docs/L3/engine/README.md` §2). `docs/L3/engine/equity-sample.md` §1 stops claiming that the sample universe is the same on every machine, because that conclusion was false of the stack the module stands on: this project's own code builds its opponent range in `Deck.STANDARD` order and never from a `set` iteration, and the library beneath it does — `calculate_equities` builds each selection's run-out deck as `list(set(deck) - counter.keys())` over cards whose hashes are string hashes — so a run is bit-reproducible only under a pinned `PYTHONHASHSEED`, which `protocol.md` §4 already recorded as `engine`'s known defect and `docs/L3/training/evidence.md` §6 measures, with `docs/L3/engine/platform.md` §5 and `docs/L3/engine/cost.md` G6.1 carrying the same qualification so no engine document contradicts this layer's protocol. Rev 12 answers D-19 and is the largest change since the league: the learning rule stops being a module constant and becomes a **catalogue** — `masked-q-learning` and `double-q-learning`, the second the direct remedy for the upward-biased maximum the R2 diagnosis measured — selected by the learner spec and recorded in a format-version-2 checkpoint, while the version-1 containers the repository ships load unchanged as the rule their writer could have used. Every variant a configuration declares is **trained**, so two variants may declare two rules and each gets its own curves, snapshots and record entry; a pool member carries its `rule` and the id digests it; and a window holding several estimators is grouped into families whose full-window eviction is fair-share rather than oldest-first, which is what lets a second family roll. `rules.md` is the new document that owns the catalogue (D-19, ASM-7, ASM-25, ASM-26, ASM-27).

## Reading order

| Document | What it answers |
|---|---|
| `getting-started.md` | the route in: Python, dependencies, `PYTHONPATH=src`, one training run, one league table |
| `gpu.md` | what runs on CPU today, why an agent cannot run the GPU path, and the commands a user runs to verify the card and measure the PyTorch-versus-NumPy difference (D-17, D-7, D-8) |
| `module-map.md` | the six modules, the league's owner, their interactions, path ownership, and the harness contract of brief §5 |
| `e2e-surface.md` | every entry point the battery drives, the shared contracts behind them, the endpoint counts in `modules.json`, and which surfaces are general-purpose |
| `records.md` | the mapping shape each entry point exchanges, the league's pool, cell, matrix and rating records included, so no module reads another's type (D-13) |
| `ladder.md` | the six rungs as configurations of one machinery, what a comparison holds constant, the budgets, and where the D-5 notebooks live |
| `rules.md` | the learning-rule catalogue: what each rule's target is, the one contract they share, what a checkpoint records, how a configuration declares several, and the fairness rule that replaces a single rule (D-19) |
| `protocol.md` | the evidence a rung must report (D-6, D-16), the three fixed baselines (ASM-4), the seed contract (ASM-2), checkpoint retention (ASM-5, D-16), and the device rule (D-8) |
| `league.md` | the pool, the scheduler, the matrix and the rating, the live and offline tables, what M, the cell size and the cells cost, and how to read a rank (D-16, ASM-13, ASM-14, ASM-21) |
| `battery.md` | what `tests/e2e/` covers, how the batteries are run, and what green means here (D-11) |
| `assumptions.md` | what L1 decided where the brief left the answer here, each with the alternative it rejected |

`modules.json` at the repository root is the declaration `strata-lint` reads (modules.md §4); `README.md` at the root is L0's front page and links this file (D-1). The game is heads-up fixed-limit Hold'em (D-2), the ladder's order is brief §2's (D-3), and the league is D-16; Phase 2 is not designed here (D-4, D-9). **A citation names the rule's carrier, never the walkthrough record**: a document cites a `D-n`, an `ASM-n` or the section that carries the rule — `battery.md` §2 for where a battery writes, `ladder.md` §7 for where a notebook writes, never the redirect a split leaves behind (`assumptions.md` ASM-24) — and never a finding, by subject or by number, in `strata/records/phase1-walkthrough.md`, because that record is replaced on every run (§7 of `strata/walkthrough.md`, D-14, ASM-22).
