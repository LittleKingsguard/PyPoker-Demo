## 1. Purpose and scope

The deck is the talk's projection surface: one static HTML file, casino-table themed, every block of content on a card, whose theme and function are testable **before any real content exists**. It ships as one file with inline CSS and JS and no network dependency, so it opens from `file://` on the talk laptop with nothing to install and no sibling to lose (D-118).

This pass is a **layout sampler with three real slides in it**: exactly eight slides — **title**, **contact**, section divider, bullets, comparison/table, chart placeholder, quote, **outtro** — in that order (D-118, D-129, D-131). The title slide carries the talk's real title and is specified in §5.1 (D-131); the two contact slides carry the speaker's real contact block and the LinkedIn QR and are specified in `docs/presentation/contact.md`; the other five are demo content, visibly marked, so a demo figure can never be misread as a measured one (§5, A4). Real numbers and the real narrative are a **later** pass (D-118 Scope). **Documents:** `presentation/README.md` (opening, controls, editing a slide; the script the D-14 walkthrough stages), `docs/presentation/contact.md` (the two contact slides, the QR drawing contract, the id remap, C1–C8), `docs/presentation/presenter.md` (`N` notes and `M` sources, P1–P11), `docs/presentation/checks.md` (the dev-only gate `presentation/check.mjs`, G1–G11, and the `FACTCHECK.md` form) and `docs/presentation/content-rules.md` (R1–R9, binding on the three real slides now and on the rest from the next content pass).
Rules L4 must not soften: no framework, no library, no build step; no `<link>`, `<img>`, `@import`, `@font-face` or `url(...)` anywhere; **no `http` substring in the file**; no `eval`, `new Function` or `innerHTML` write; CSS and JS inline, the JS one dependency-free IIFE that uses `requestAnimationFrame` only to coalesce resize. The one URL on the contact slides is written with its scheme's first letter as a character reference (`&#104;ttps://…`), so the printed address is complete while that grep stays at zero (§7 A2, contact.md §2).

## 2. The stage

**Design surface: 1280×720 CSS px, fixed.** `--scale: min(innerWidth/1280, innerHeight/720)`, unrounded, written to `:root` and consumed as `transform: scale(var(--scale))` on `#stage`, which stays a 1280×720 box centred by `position: fixed; left: 50%; top: 50%; margin-left: -640px; margin-top: -360px`. Letterboxing is **felt, not bars** — the body carries the table field at window size (§3) — so the surround is more table and any aspect ratio looks deliberate. 1920×1080 is exactly ×1.5; a smaller window shrinks the whole deck; **nothing ever reflows** (§8). **Resize:** one `resize` listener sets `dirty`; a single `requestAnimationFrame` reads `innerWidth`/`innerHeight` once per frame and writes `--scale` — no layout read in the handler, no timers. The **first** `--scale` is written synchronously before the first paint (a first frame at scale 1 is a visible flash on any window that is not 1280×720), and rAF coalesces later resizes only. `#stage` and `.card` are `overflow: hidden` — necessary, not sufficient: the clipping rule is the next paragraph.

**Overflow is structural, and the boxes that clip are named.** Every text block is a **fixed-height box** (`height: Npx`) from §5's budget and each shape's heights sum to ≤ its card's inner height; a height alone never clips, `overflow: hidden` does. The standing rule has three tiers, all under `html.js` so the no-JS document stays a readable stack (§6): `.card { overflow: hidden }`; `.card > *:not(.suit) { overflow: hidden }`; and the fixed-height boxes one level deeper than `.card` clip themselves — `.t-list li` (38px), `.t-group p` (76px), `.t-table th`/`td` (44px), and the contact slides' own deep boxes, the 28px `.t-url` line spans, enumerated per slide in `contact.md` §3 — of which the table cells **also** carry `white-space: nowrap` so a row stays 44px. The rule exists because of a defect that was measured against the earlier form of it: with clipping reaching only `.card`'s direct children, a wrapped bullet painted its second line across the 16px separator and over the next bullet, a long side note overprinted the next `.t-group`, and a long cell grew its row. `nowrap` is the second half of the fix, not decoration: a cell's `height` is a **minimum** in this engine, so clipping the cell alone still left a 79px row, and one unwrapped line is what holds 44px.
**What shipped, and what is still the arbiter.** The rule now covers descendants and is in the file as written above; the rendered test still decides whether that form suffices (A8b), because a selector is not evidence. **Two tests, two purposes:** A8(b) is a *mechanism* test whose injected copy is expected to clip — that is the mechanism working — while the **shipped** copy must not clip at all: §5's character budgets are how a block stays inside its box, and the gate's G4 (`docs/presentation/checks.md` §3.1) flags any hidden text, vertically or horizontally, in the file as it ships. **`.card`'s own `overflow: hidden` is not that guarantee:** it clips at the card's 512px inner edge, long after a second line has buried the separator and its neighbour.
Stage arithmetic: `44 + 1192 + 44 = 1280` wide, `44 + 568 + 24 + 40 + 44 = 720` tall (padding 44, slide 568, gap 24, HUD 40); the slide content box is 1192×568.

## 5. Slide shapes

Eight slides `#s1`–`#s8`, `data-shape` in this order (A3): **`title` · `contact` · `divider` · `bullets` · `comparison` · `chart` · `quote` · `outtro`** — eight values, the whole vocabulary, one per shape.
**`data-shape` is a label, never a lever:** no CSS rule keys on it and no JS branch keys on it, so nothing about layout, theme or navigation can change with it; its one consumer is the `#live` line, `Slide n of 8 — shape`, so a value outside the declared list is a defect (A3) rather than a feature. **The vocabulary grows here and only here:** a ninth slide adds its new word to this paragraph and to A3's ordered list **in the same change** as its own `#sN` height rules, its own `#sN`-scoped clip/`nowrap` rules and its extra `.dot` (`presentation/README.md`, §Editing a slide, which is the ordered recipe). It must not reuse one of these eight words: `#live` would then announce a shape the slide is not. Nothing keys on the attribute, so the whole cost of a new word is one line here.
Budgets are literal px, top-down inside the card's inner box; each sum is at or under that box, and every line count is a fixed-height block. **Five slides are demo and three are real:** the demo slides' badge reads `DEMO`, the HUD reads `demo slides: placeholder content`, and no demo slide carries a real figure; `#s1` carries the talk's real title (D-131), `#s2` and `#s8` the real contact block, and none of the three carries a badge or a figure (`contact.md` §4).

## 6. Navigation

**Keys**, on `keydown`, `preventDefault()` only for these: `→`/`↓`/`PageDown`/`Space` next · `←`/`↑`/`PageUp`/`Shift+Space` previous · `Home` first · `End` last · `f`/`F` fullscreen. Next/previous **clamp** at the ends: never wrap, never scroll. Shift+Space is previous, so a held Space never races forward. `N`, `M` and `Esc` belong to presenter mode and are specified in `docs/presentation/presenter.md` §4. **A held `Ctrl`, `Alt` or `Meta` disables every deck key**, presenter keys included: browser shortcuts are not hijacked, so `Ctrl+←`, `Ctrl+PageDown` and `Alt+←` keep going to the browser, and the deck's handler returns before it looks at the key.
**Wheel:** accumulate `deltaY`, fire one step at **±60 px**, reset on direction change, after **250 ms** of quiet or after any step, and drop wheel events for **400 ms** after a navigation; `passive: true`, no `preventDefault` needed because the document cannot scroll under `html.js`.

**Click zones**, on the viewport (letterbox included), primary button only, as fractions of `innerWidth`: `x < 0.30` previous, `x > 0.70` next, `0.30 ≤ x ≤ 0.70` **inert** (text stays selectable in the middle).
**Hash:** `#/N`, N = 1..8 (the deck's slide total, A3 — the range moves with it), 1-based; read on load with `^#\/(\d{1,2})$`, clamped into range, absent or unmatched → 1. A change writes `location.hash = '#/' + n`. **Out-of-range is clamped for display and the address bar keeps what was typed:** `#/99` shows slide 8 while the bar still reads `#/99`, and the bar is rewritten to the true index **only by a move that changes slides** — a step press *at* the clamped end (`→` on `#/99`, which is already slide 8) is a no-op under the clamp and rewrites nothing, so the bar stays stale until a press that actually moves, e.g. `←` to `#/7`. **The clamped low end behaves identically, and it is the one a typo reaches** (`#/0`, or a `#/1` with its digit deleted): the parse and clamp of A11 put slide **1** on screen while the bar still reads `#/0`, the first `→` is a move that changes slides and rewrites the bar to `#/2`, and `←` on slide 1 is the clamped no-op that rewrites nothing, so `#/0` survives in the bar until a press that moves. **That is documented, not normalised on load**, deliberately: a load-time normalisation is a second writer running ahead of `show()`'s first call, and it pushes a history entry, so one Back press would then appear to do nothing. The presented surface is the slide and its counter, never the address bar; in fullscreen the bar is not on screen at all, and the gate asserts the counter for this reason (`docs/presentation/checks.md` G3). **Which history API and why:** the fragment assignment, not `pushState`/`replaceState` — Firefox refuses those on a `file://` document (opaque origin) and Firefox on `file://` is the deck's target, while a hash write always works there and still leaves a back-entry, so back/forward walk the slides. Back and forward arrive as **`popstate`** (with `hashchange` beside it, since Firefox fires both on a fragment traversal): both call `show(indexFromHash(), {writeHash: false})`, and `show` no-ops when that index is already active, so the double event costs one comparison and cannot loop. The write is wrapped in `try/catch`: refused, the deck still navigates and only the address bar goes stale.

**HUD and announcement:** the 40px footer on the felt carries eight progress dots (`.dots`, active filled `--gold`, the rest `--gold-dim` at **70%** — ≈3:1 on the felt, the non-text threshold, and only an indicator: the counter carries the same fact), the counter `n / 8` in `--font-mono`, the static hint `← → space · F`, and **one pointer-enabled control**, `button.more-btn` (sources; `aria-disabled` on a slide that has none, `docs/presentation/presenter.md` §3), inside a strip that is otherwise `pointer-events: none`; the strip's 40px and §2's row arithmetic are unchanged by it. The hint is on the audience's screen, so it never advertises the presenter keys. A hidden `#live[role="status"][aria-live="polite"]` receives "Slide n of 8 — shape" on every change, clipped rather than `display:none` (a `display:none` live region is announced by nobody), and it never carries a note or a source. The static `.demo-note` reads `demo slides: placeholder content`, which is true on all eight slides — the three real slides (`#s1` the talk's title, `#s2` and `#s8` the contact block) are real and carry no badge (`contact.md` §4).

**Fullscreen:** `f`/`F` calls `requestFullscreen()` only when `document.fullscreenEnabled` and the method exist, inside a `try` with `.catch(function () {})`; unsupported or refused is a silent no-op and navigation never depends on it. **`Esc` is the browser's for fullscreen and presenter mode's for an open panel** (`presenter.md` §4): nothing depends on which of the two receives it, because `N` and `M` also toggle and the panel carries a close button.
**Motion:** a 320 ms opacity/8px-translate CSS enter transition (added only on a navigation, so the first frame is opaque); `@media (prefers-reduced-motion: reduce)` sets it to `none` and the JS reads `matchMedia('(prefers-reduced-motion: reduce)').matches` to skip the enter pass — there is no rAF enter path anywhere (§1).
**No JS:** the base CSS is a readable stacked document — every scaling, `position: fixed`, `overflow: hidden` and single-slide rule is scoped under `html.js`, which the IIFE's first statement adds. With JS off all eight slides render in order as one long 1280px page, the HUD is hidden, and no slide is lost. The presenter drawer is hidden above `html.js` and the notes are inert `<template>` content, so the stacked document contains no notes and no sources at all (`presenter.md` §1, §4).

## 7. Acceptance checks
Static checks are `grep`/read on the file; **render** checks use exactly `firefox --headless --no-remote --profile /tmp/dshshot/profile --screenshot OUT.png --window-size=1280,720 "file://<abs>/presentation/index.html#/N"`, or `node presentation/check.mjs`, which drives the same renders through WebDriver BiDi and adds the geometry checks G1–G11 (`docs/presentation/checks.md`). A keypress check is **code-review-only** and says so. The two contact slides add `contact.md` C1–C8, of which C8 is the rendered decode and is reviewer-only.

A1. `presentation/index.html` exists, ≥ 12 kB, exactly one `<style>` and one `<script>`, neither with `src`/`href`.
A2. `grep -c 'http'` = **0**; no `url(`, `@import`, `@font-face`, `<link`, `<img`, `src=` anywhere. ## 8. Rejected alternatives

| Rejected | Why it lost |
|---|---|
| A slides framework — reveal.js, impress.js, any vendored or CDN copy | A network fetch or a second file to lose on the talk laptop, and its DOM owns the theme: the card primitive and the 1280×720 budget would be fought instead of stated (D-118) |
| Texture from an inline SVG `feTurbulence` data-URI | Its `xmlns` necessarily contains an `http://` string, so "no network dependency" stops being a one-line grep; a 3px gradient crosshatch gives the felt weave wanted, at no decode cost |
| A fluid stage — `clamp()`/`vmin` sizes, no fixed surface — or CSS-only scaling | CSS cannot divide two lengths, so `min(vw/1280, vh/720)` needs JS anyway; and fluid makes "never overflows" a function of the window instead of a sum of px, the one property A8 must add up |
| One `<iframe>` per slide, scaled to the window | Nested documents, a second copy of the theme, and no shared hash; the single-file rule of D-118 is the point |
| Continuous scroll / `scroll-snap` instead of discrete slides | A stray scroll puts two slides on a projector mid-sentence (D-118 rejected) |
| `pushState`/`replaceState` for the slide index | Refused or unreliable on a `file://` document in the target browser; the hash is the one history write that always works and still leaves a back-entry (§6) |
| A Markdown/JSON source plus a build step | A toolchain on the talk machine to edit text, and a stale `index.html` when it is not run (D-118 rejected) |
| The QR as a base64 PNG, as a code generated by a library, or inverted/tinted to match the felt | An `<img src>` or `url(data:…)` breaks the no-image rule and its greps and puts an opaque blob in a file people edit by hand; no QR library is installed and the user's own asset is the authority for their profile link; contrast and quiet zone are what make a code scannable, so neither is a styling choice (D-129, `contact.md` §2) |
