## 1. Purpose and scope

The deck is the talk's projection surface: one static HTML file, casino-table themed, every block of content on a card, so it opens from `file://` on the talk laptop with nothing to install and no sibling to lose (D-118 — only the deck is ever copied to the talk machine; `figures/` travels with the repo, A16).

This pass is **no longer a sampler at all**: exactly **nine slides, every one of them real** — **title**, **contact**, **the plan**, **the pivot** (dead-trunk grid), **the live-trunk grid**, **the trunk figure**, **the card-model divider**, **the card-model opening**, and the **outtro** last (§5, `content.md` §1). The five demo sampler slides (**divider, bullets, comparison, chart, quote**) were **deleted** by D-133, their `#sN` rules and their `DEMO` badges with them, so **no slide carries a badge and the HUD carries no demo note** (A4, §5.3). **Documents:** `presentation/README.md` (opening, controls, editing a slide, the figures and how to regenerate them — the script the D-14 walkthrough stages), `docs/presentation/contact.md` (`#s2` and `#s9`, the QR drawing contract, C1–C8), **`docs/presentation/content.md` (`#s3`–`#s8`: their px sums, copy, surfaces, C9–C16, and the four `FACTCHECK.md` rows)**, `docs/presentation/presenter.md` (notes on all nine slides and sources on four, §1.1's notes for the six content slides, P1–P12), `docs/presentation/checks.md` (the dev-only gate `presentation/check.mjs`, G1–**G12**, and the `FACTCHECK.md` form) and `docs/presentation/content-rules.md` (R1–R9).
Rules L4 must not soften: no framework, no library, no build step; no `<link>`, `@import`, `@font-face` or `url(...)` anywhere in the deck's own CSS; **no `http` substring in the file**; no `eval`, `new Function` or `innerHTML` write; CSS and JS inline, the JS one dependency-free IIFE that uses `requestAnimationFrame` only to coalesce resize. **`<img>` and `src` are no longer banned outright — A2 replaces that ban with the rule that every `src` is relative, resolves inside this repo, and carries no scheme** (D-132). The one URL on the contact slides is written with its scheme's first letter as a character reference (`&#104;ttps://…`), so the printed address is complete while that grep stays at zero (§7 A2, `contact.md` §2).

## 2. The stage

**Design surface: 1280×720 CSS px, fixed.** `--scale: min(innerWidth/1280, innerHeight/720)`, unrounded, written to `:root` and consumed as `transform: scale(var(--scale))` on `#stage`, which stays a 1280×720 box centred by `position: fixed; left: 50%; top: 50%; margin-left: -640px; margin-top: -360px`. Letterboxing is **felt, not bars** — the body carries the table field at window size (§3) — so the surround is more table and any aspect ratio looks deliberate. 1920×1080 is exactly ×1.5; a smaller window shrinks the whole deck; **nothing ever reflows** (§8). **Resize:** one `resize` listener sets `dirty`; a single `requestAnimationFrame` reads `innerWidth`/`innerHeight` once per frame and writes `--scale` — no layout read in the handler, no timers. The **first** `--scale` is written synchronously before the first paint (a first frame at scale 1 is a visible flash on any window that is not 1280×720), and rAF coalesces later resizes only. `#stage` and `.card` are `overflow: hidden` — necessary, not sufficient: the clipping rule is the next paragraph.

**Overflow is structural, and the boxes that clip are named.** Every text block is a **fixed-height box** (`height: Npx`) from §5's and `content.md`'s budgets and each shape's heights sum to ≤ its container's inner height; a height alone never clips, `overflow: hidden` does. The standing rule has three tiers, all under `html.js` so the no-JS document stays a readable stack (§6): `.card { overflow: hidden }`; `.card > *:not(.suit) { overflow: hidden }`; and the boxes one level deeper clip themselves — `#s3`'s `.t-plan` row (104px) with its `.t-num` (64px) and `.t-step` (36px), and the two contact slides' 28px `.t-url` line spans (`contact.md` §3) — of which the plan's two spans and the `.t-url` spans **also** carry `white-space: nowrap`. The rule exists because of a defect that was measured against the earlier form of it: with clipping reaching only `.card`'s direct children, a wrapped line in a deeper box painted its second line outside its own px box and over its neighbour, and a long line grew its row. `nowrap` is the second half of the fix, not decoration: a box's `height` is a **minimum** in this engine, so clipping the inner box alone still left a grown row, and one unwrapped line is what holds the px. **`nowrap` is also why `content.md`'s plan rows carry it** — the same minimum-height rule would grow a 104px row.
**What shipped, and what is still the arbiter.** The rule now covers descendants and is in the file as written above; the rendered test still decides whether that form suffices (A8b), because a selector is not evidence. **Two tests, two purposes:** A8(b) is a *mechanism* test whose injected copy is expected to clip — that is the mechanism working — while the **shipped** copy must not clip at all: the character budgets are how a block stays inside its box, and the gate's G4 flags any hidden text, vertically or horizontally, in the file as it ships. **`.card`'s own `overflow: hidden` is not that guarantee:** it clips at the card's 512px inner edge, long after a second line has buried its neighbour.
Stage arithmetic: `44 + 1192 + 44 = 1280` wide, `44 + 568 + 24 + 40 + 44 = 720` tall (padding 44, slide 568, gap 24, HUD 40); the slide content box is 1192×568. **The card interior is 568 − 2×28 = 512, and the difference matters:** the card shapes place an ivory `article.card` (interior 512), while `#s4`, `#s5` and `#s8` place **the fragment's plate or a figure directly on the felt** and so spend the full **568** — which is exactly the room that takes the grids from D-132's rejected 0.40 scale to `content.md` §3's 0.96 and 0.94.

## 6. Navigation

**Keys**, on `keydown`, `preventDefault()` only for these: `→`/`↓`/`PageDown`/`Space` next · `←`/`↑`/`PageUp`/`Shift+Space` previous · `Home` first · `End` last · `f`/`F` fullscreen. Next/previous **clamp** at the ends: never wrap, never scroll. Shift+Space is previous, so a held Space never races forward. `N`, `M` and `Esc` belong to presenter mode (`presenter.md` §4). **A held `Ctrl`, `Alt` or `Meta` disables every deck key**, presenter keys included: browser shortcuts are not hijacked, and the handler returns before it looks at the key.
**Wheel:** accumulate `deltaY`, fire one step at **±60 px**, reset on direction change, after **250 ms** of quiet or after any step, and drop wheel events for **400 ms** after a navigation; `passive: true`, no `preventDefault` needed because the document cannot scroll under `html.js`.
**Click zones**, on the viewport (letterbox included), primary button only, as fractions of `innerWidth`: `x < 0.30` previous, `x > 0.70` next, `0.30 ≤ x ≤ 0.70` **inert** (text stays selectable in the middle).
**Hash:** `#/N`, N = 1..9 (the deck's slide total, A3 — the range moves with it), 1-based; read on load with `^#\/(\d{1,2})$`, clamped into range, absent or unmatched → 1. A change writes `location.hash = '#/' + n`. **Out-of-range is clamped for display and the address bar keeps what was typed:** `#/99` shows slide 9 while the bar still reads `#/99`, and the bar is rewritten to the true index **only by a move that changes slides** — a step press *at* the clamped end (`→` on `#/99`) is a no-op under the clamp and rewrites nothing; `←` to `#/8` rewrites it. **The clamped low end behaves identically** (`#/0`, or a `#/1` with its digit deleted): slide **1** on screen while the bar reads `#/0`, the first `→` rewrites it to `#/2`, and `←` on slide 1 rewrites nothing. **That is documented, not normalised on load**, deliberately: a load-time normalisation is a second writer running ahead of `show()`'s first call and pushes a history entry, so one Back press would then appear to do nothing. The presented surface is the slide and its counter, never the address bar; in fullscreen the bar is not on screen at all, and the gate asserts the counter (G3). **Which history API and why:** the fragment assignment, not `pushState`/`replaceState` — Firefox refuses those on a `file://` document (opaque origin) and Firefox on `file://` is the deck's target, while a hash write always works there and still leaves a back-entry, so back/forward walk the slides. Back and forward arrive as **`popstate`** (with `hashchange` beside it, since Firefox fires both on a fragment traversal): both call `show(indexFromHash(), {writeHash: false})`, and `show` no-ops when that index is already active.
**HUD and announcement:** the 40px footer on the felt carries **nine** progress dots (`.dots`, active filled `--gold`, the rest `--gold-dim` at **70%** — ≈3:1 on the felt, the non-text threshold, and only an indicator: the counter carries the same fact), the counter `n / 9` in `--font-mono`, the static hint `← → space · F`, and **one pointer-enabled control**, `button.more-btn` (sources; `aria-disabled` on a slide that has none, `presenter.md` §3), inside a strip that is otherwise `pointer-events: none`. The hint never advertises the presenter keys. A hidden `#live[role="status"][aria-live="polite"]` receives "Slide n of 9 — shape" on every change, clipped rather than `display:none`. **There is no demo note in the HUD and no `DEMO` badge on any slide** — D-133 deleted `.demo-note` with the sampler, so the strip holds nothing but dots, counter, hint and `More` (A4).
**Fullscreen:** `f`/`F` calls `requestFullscreen()` only when `document.fullscreenEnabled` and the method exist, inside a `try` with `.catch(function () {})`; unsupported or refused is a silent no-op and navigation never depends on it. **`Esc` is the browser's for fullscreen and presenter mode's for an open panel**; nothing depends on which receives it, because `N` and `M` also toggle (`presenter.md` §4).
**Motion:** a 320 ms opacity/8px-translate CSS enter transition (added only on a navigation, so the first frame is opaque); `@media (prefers-reduced-motion: reduce)` sets it to `none` and the JS reads `matchMedia('(prefers-reduced-motion: reduce)').matches` to skip the enter pass — there is no rAF enter path anywhere (§1).
**No JS:** the base CSS is a readable stacked document — every scaling, `position: fixed`, `overflow: hidden` and single-slide rule is scoped under `html.js`, which the IIFE's first statement adds. With JS off all nine slides render in order as one long 1280px page, the HUD is hidden, and no slide is lost. **The figures still load** — an `<img>` to a relative path is exactly how a no-JS document shows a picture, which is one more reason A2 allows it. The presenter drawer is hidden above `html.js` and the notes are inert `<template>` content, so the stacked document contains no notes and no sources.

## 8. Rejected alternatives

| Rejected | Why it lost |
|---|---|
| A slides framework — reveal.js, impress.js, any vendored or CDN copy | A network fetch or a second file to lose on the talk laptop, and its DOM owns the theme: the card primitive and the 1280×720 budget would be fought instead of stated (D-118) |
| Texture from an inline SVG `feTurbulence` data-URI | Its `xmlns` necessarily contains an `http://` string, so "no network dependency" stops being a one-line grep; a 3px gradient crosshatch gives the felt weave wanted, at no decode cost |
| A fluid stage — `clamp()`/`vmin` sizes, no fixed surface — or CSS-only scaling | CSS cannot divide two lengths, so `min(vw/1280, vh/720)` needs JS anyway; and fluid makes "never overflows" a function of the window instead of a sum of px, the one property A8 must add up |
| One `<iframe>` per slide, scaled to the window | Nested documents, a second copy of the theme, and no shared hash; the single-file rule of D-118 is the point |
| Continuous scroll / `scroll-snap` instead of discrete slides | A stray scroll puts two slides on a projector mid-sentence (D-118 rejected) |
| `pushState`/`replaceState` for the slide index | Refused or unreliable on a `file://` document in the target browser; the hash is the one history write that always works and still leaves a back-entry (§6) |
| A Markdown/JSON source plus a build step | A toolchain on the talk machine to edit text, and a stale `index.html` when it is not run (D-118 rejected) |
| The QR as a base64 PNG, as a code generated by a library, or inverted/tinted to match the felt | An `<img src>` or `url(data:…)` breaks the no-image rule and its greps and puts an opaque blob in a file people edit by hand; no QR library is installed and the user's own asset is the authority for their profile link (D-129, `contact.md` §2) |
| Inlining `network-compare.svg`, or re-drawing the figures by hand | 61 kB of matplotlib with `xmlns`, five `http` strings and 172 `url(#…)` refs would end A2's greps, and a hand-drawn copy has no provenance and drifts from the record (D-132) |
| Both reference grids on one slide, or a grid inside an ivory card | 0.40 scale and ≈5.6 px type is a projected grid nobody can read, and the card's 28px padding plus the plate's 22px takes 100px of width and height and halves the scale again (`content.md` §3) |
| Keeping the demo sampler slides at the tail, or deleting only their `DEMO` badges | The sampler was scaffolding for theme work and a talk does not end on placeholder copy; stripping the badges alone would leave that copy on stage unmarked, which is the one thing the badges exist to prevent — so the five slides and their CSS went (D-133, §5.3) |
