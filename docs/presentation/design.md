## 1. Purpose and scope

The deck is the talk's projection surface: one static HTML file, casino-table themed, every block of content on a card, whose theme and function are testable **before any real content exists**. It ships as one file with inline CSS and JS and no network dependency, so it opens from `file://` on the talk laptop with nothing to install and no sibling to lose (D-118).

This pass is a **layout sampler**: exactly seven slides, one per content shape — title, section divider, bullets, comparison/table, chart placeholder, quote, closing — in that order (D-118). Every slide is demo content, visibly marked, so a demo figure can never be misread as a measured one (§5, A4); real content and real numbers are a **later** pass (D-118 Scope). **Documents:** `presentation/README.md` (opening, controls, editing a slide; the script the D-14 walkthrough stages), `docs/presentation/presenter.md` (`N` notes and `M` sources, P1–P10), `docs/presentation/checks.md` (the dev-only gate `presentation/check.mjs`, G1–G10, and the `FACTCHECK.md` form) and `docs/presentation/content-rules.md` (R1–R9, binding from the next content pass).
Rules L4 must not soften: no framework, no library, no build step; no `<link>`, `<img>`, `@import`, `@font-face` or `url(...)` anywhere; **no `http` substring in the file**; no `eval`, `new Function` or `innerHTML` write; CSS and JS inline, the JS one dependency-free IIFE that uses `requestAnimationFrame` only to coalesce resize.

## 2. The stage

**Design surface: 1280×720 CSS px, fixed.** `--scale: min(innerWidth/1280, innerHeight/720)`, unrounded, written to `:root` and consumed as `transform: scale(var(--scale))` on `#stage`, which stays a 1280×720 box centred by `position: fixed; left: 50%; top: 50%; margin-left: -640px; margin-top: -360px`. Letterboxing is **felt, not bars** — the body carries the table field at window size (§3) — so the surround is more table and any aspect ratio looks deliberate. 1920×1080 is exactly ×1.5; a smaller window shrinks the whole deck; **nothing ever reflows** (§8). **Resize:** one `resize` listener sets `dirty`; a single `requestAnimationFrame` reads `innerWidth`/`innerHeight` once per frame and writes `--scale` — no layout read in the handler, no timers. The **first** `--scale` is written synchronously before the first paint (a first frame at scale 1 is a visible flash on any window that is not 1280×720), and rAF coalesces later resizes only. `#stage` and `.card` are `overflow: hidden` — necessary, not sufficient: the clipping rule is the next paragraph.

**Overflow is structural, and the boxes that clip are named.** Every text block is a **fixed-height box** (`height: Npx`) from §5's budget and each shape's heights sum to ≤ its card's inner height; a height alone never clips, `overflow: hidden` does. The standing rule has three tiers, all under `html.js` so the no-JS document stays a readable stack (§6): `.card { overflow: hidden }`; `.card > *:not(.suit) { overflow: hidden }`; and the fixed-height boxes one level deeper than `.card` clip themselves — `.t-list li` (38px), `.t-group p` (76px), `.t-table th`/`td` (44px) — of which the table cells **also** carry `white-space: nowrap` so a row stays 44px. The rule exists because of a defect that was measured against the earlier form of it: with clipping reaching only `.card`'s direct children, a wrapped bullet painted its second line across the 16px separator and over the next bullet, a long side note overprinted the next `.t-group`, and a long cell grew its row. `nowrap` is the second half of the fix, not decoration: a cell's `height` is a **minimum** in this engine, so clipping the cell alone still left a 79px row, and one unwrapped line is what holds 44px.
**What shipped, and what is still the arbiter.** The rule now covers descendants and is in the file as written above; the rendered test still decides whether that form suffices (A8b), because a selector is not evidence. **Two tests, two purposes:** A8(b) is a *mechanism* test whose injected copy is expected to clip — that is the mechanism working — while the **shipped** copy must not clip at all: §5's character budgets are how a block stays inside its box, and the gate's G4 (`docs/presentation/checks.md` §3.1) flags any hidden text, vertically or horizontally, in the file as it ships. **`.card`'s own `overflow: hidden` is not that guarantee:** it clips at the card's 512px inner edge, long after a second line has buried the separator and its neighbour.
Stage arithmetic: `44 + 1192 + 44 = 1280` wide, `44 + 568 + 24 + 40 + 44 = 720` tall (padding 44, slide 568, gap 24, HUD 40); the slide content box is 1192×568.

**Max 3 cards per slide** (S7 uses three; no slide uses more); columns add to `1192` and rows to `568` exactly. **Decoration allowed, and only this:** one suit glyph top-left and the same glyph rotated 180° bottom-right (`.suit.suit--tl`, `.suit.suit--br`, `--gold-dim` for spades/clubs and `--suit-red` for hearts/diamonds, 34px); the 2px brass rim inside `--card-shadow`; a 1px hairline rule under a card heading (`.card__rule`); the rail behind all cards. **Every** decorative glyph — these, the divider's suit circle, the closing pips — carries `aria-hidden="true"`, so no screen reader reads a suit mid-sentence. **Not allowed:** any image, any texture or gradient on the face, any size off §3's ramp, any text shadow. ## 5. Slide shapes

Seven slides `#s1`–`#s7`, `data-shape` in this order (A3): **`title` · `divider` · `bullets` · `comparison` · `chart` · `quote` · `closing`** — seven values, the whole vocabulary, one per shape.
**`data-shape` is a label, never a lever:** no CSS rule keys on it and no JS branch keys on it, so nothing about layout, theme or navigation can change with it; its one consumer is the `#live` line, `Slide n of 7 — shape`, so a value outside the declared list is a defect (A3) rather than a feature. **The vocabulary grows here and only here:** an eighth slide adds its new word to this paragraph and to A3's ordered list **in the same change** as its own `#sN` height rules, its own `#sN`-scoped clip/`nowrap` rules and its extra `.dot` (`presentation/README.md`, §Editing a slide, which is the ordered recipe). It must not reuse one of these seven words: `#live` would then announce a shape the slide is not. Nothing keys on the attribute, so the whole cost of a new word is one line here.
Budgets are literal px, top-down inside the card's inner box; each sum is at or under that box, and every line count is a fixed-height block. All copy is demo: the badge reads `DEMO`, the HUD reads `placeholder content — not measured`, and no slide carries a real figure.
**Character budgets — approximate, and deliberately conservative.** From §3's ramp at `--fs-body`'s 28px, allow ≈18px per character (a generous advance, so the counts err short) over each block's own inner width: a `#s3` bullet (`.t-list li`, one 38px line across 1136px) holds **≈62 characters**; a `#s4` side note (`.t-group p`, 2×38px inside a 76px box on a 336px inner width) **≈36, at most ≈18 a line**; a `#s4` table cell (one 44px line, ≈232px per column) **≈13**. Headings, notes and captions are one line each; the quote is 3 lines, the display headline 2. Over budget, shorten the copy — never the px (A8).

## 6. Navigation

**Keys**, on `keydown`, `preventDefault()` only for these: `→`/`↓`/`PageDown`/`Space` next · `←`/`↑`/`PageUp`/`Shift+Space` previous · `Home` first · `End` last · `f`/`F` fullscreen. Next/previous **clamp** at the ends: never wrap, never scroll. Shift+Space is previous, so a held Space never races forward. `N`, `M` and `Esc` belong to presenter mode and are specified in `docs/presentation/presenter.md` §4. **A held `Ctrl`, `Alt` or `Meta` disables every deck key**, presenter keys included: browser shortcuts are not hijacked, so `Ctrl+←`, `Ctrl+PageDown` and `Alt+←` keep going to the browser, and the deck's handler returns before it looks at the key.
**Wheel:** accumulate `deltaY`, fire one step at **±60 px**, reset on direction change, after **250 ms** of quiet or after any step, and drop wheel events for **400 ms** after a navigation; `passive: true`, no `preventDefault` needed because the document cannot scroll under `html.js`.

**Click zones**, on the viewport (letterbox included), primary button only, as fractions of `innerWidth`: `x < 0.30` previous, `x > 0.70` next, `0.30 ≤ x ≤ 0.70` **inert** (text stays selectable in the middle).
**Hash:** `#/N`, N = 1..7 (the deck's slide total, A3 — the range moves with it), 1-based; read on load with `^#\/(\d{1,2})$`, clamped into range, absent or unmatched → 1. A change writes `location.hash = '#/' + n`. **Out-of-range is clamped for display and the address bar keeps what was typed:** `#/99` shows slide 7 while the bar still reads `#/99`, and the bar is rewritten to the true index **only by a move that changes slides** — a step press *at* the clamped end (`→` on `#/99`, which is already slide 7) is a no-op under the clamp and rewrites nothing, so the bar stays stale until a press that actually moves, e.g. `←` to `#/6`. **The clamped low end behaves identically, and it is the one a typo reaches** (`#/0`, or a `#/1` with its digit deleted): the parse and clamp of A11 put slide **1** on screen while the bar still reads `#/0`, the first `→` is a move that changes slides and rewrites the bar to `#/2`, and `←` on slide 1 is the clamped no-op that rewrites nothing, so `#/0` survives in the bar until a press that moves. **That is documented, not normalised on load**, deliberately: a load-time normalisation is a second writer running ahead of `show()`'s first call, and it pushes a history entry, so one Back press would then appear to do nothing. The presented surface is the slide and its counter, never the address bar; in fullscreen the bar is not on screen at all, and the gate asserts the counter for this reason (`docs/presentation/checks.md` G3). **Which history API and why:** the fragment assignment, not `pushState`/`replaceState` — Firefox refuses those on a `file://` document (opaque origin) and Firefox on `file://` is the deck's target, while a hash write always works there and still leaves a back-entry, so back/forward walk the slides. Back and forward arrive as **`popstate`** (with `hashchange` beside it, since Firefox fires both on a fragment traversal): both call `show(indexFromHash(), {writeHash: false})`, and `show` no-ops when that index is already active, so the double event costs one comparison and cannot loop. The write is wrapped in `try/catch`: refused, the deck still navigates and only the address bar goes stale.

**HUD and announcement:** the 40px footer on the felt carries seven progress dots (`.dots`, active filled `--gold`, the rest `--gold-dim` at **70%** — ≈3:1 on the felt, the non-text threshold, and only an indicator: the counter carries the same fact), the counter `n / 7` in `--font-mono`, the static hint `← → space · F`, and **one pointer-enabled control**, `button.more-btn` (sources; `aria-disabled` on a slide that has none, `docs/presentation/presenter.md` §3), inside a strip that is otherwise `pointer-events: none`; the strip's 40px and §2's row arithmetic are unchanged by it. The hint is on the audience's screen, so it never advertises the presenter keys. A hidden `#live[role="status"][aria-live="polite"]` receives "Slide n of 7 — shape" on every change, clipped rather than `display:none` (a `display:none` live region is announced by nobody), and it never carries a note or a source.

**Fullscreen:** `f`/`F` calls `requestFullscreen()` only when `document.fullscreenEnabled` and the method exist, inside a `try` with `.catch(function () {})`; unsupported or refused is a silent no-op and navigation never depends on it. **`Esc` is the browser's for fullscreen and presenter mode's for an open panel** (`presenter.md` §4): nothing depends on which of the two receives it, because `N` and `M` also toggle and the panel carries a close button.
**Motion:** a 320 ms opacity/8px-translate CSS enter transition (added only on a navigation, so the first frame is opaque); `@media (prefers-reduced-motion: reduce)` sets it to `none` and the JS reads `matchMedia('(prefers-reduced-motion: reduce)').matches` to skip the enter pass — there is no rAF enter path anywhere (§1).
**No JS:** the base CSS is a readable stacked document — every scaling, `position: fixed`, `overflow: hidden` and single-slide rule is scoped under `html.js`, which the IIFE's first statement adds. With JS off all seven slides render in order as one long 1280px page, the HUD is hidden, and no slide is lost. The presenter drawer is hidden above `html.js` and the notes are inert `<template>` content, so the stacked document contains no notes and no sources at all (`presenter.md` §1, §4).

## 7. Acceptance checks
Static checks are `grep`/read on the file; **render** checks use exactly `firefox --headless --no-remote --profile /tmp/dshshot/profile --screenshot OUT.png --window-size=1280,720 "file://<abs>/presentation/index.html#/N"`, or `node presentation/check.mjs`, which drives the same renders through WebDriver BiDi and adds the geometry checks G1–G10 (`docs/presentation/checks.md`). A keypress check is **code-review-only** and says so.

A1. `presentation/index.html` exists, ≥ 12 kB, exactly one `<style>` and one `<script>`, neither with `src`/`href`.
A2. `grep -c 'http'` = **0**; no `url(`, `@import`, `@font-face`, `<link`, `<img`, `src=` anywhere.
A3. Exactly seven `<section class="slide"`, `data-shape` in file order `title divider bullets comparison chart quote closing`. **This number is the deck's slide total and it appears in three places that move together** — A3's sections, A4's seven badges, A9's `#/7` three-card slide — while the gate holds no copy of it: `presentation/check.mjs` derives the total from the deck it loads and prints `slides: N (derived from section.slide)` (`docs/presentation/checks.md` §4, G3), so a count that moved without the documents is visible in the check output.
A4. Seven `class="demo-badge"`; the chart slide contains `not measured`; the HUD contains `placeholder content`.
A5. `grep -c 'pushState\|replaceState'` = 0; `location.hash`, `popstate`, `hashchange` all present.
A6. `prefers-reduced-motion` ≥ 1; `requestFullscreen` has one call site inside a guarded `try` + `.catch`, behind both the `fullscreenEnabled` and `typeof … === 'function'` checks; `requestAnimationFrame` only in the resize path; no `eval`, `new Function` or `innerHTML`.
A7. Contrast re-derived from the file's own `:root` hex values: `--ink` on `--card-face` ≥ 12:1 and `--gold` on `--felt-2` ≥ 4.5:1 (§3 states 13.4 and 7.5).
A8. **Overflow, in two parts: the sum is necessary, the rendered test is sufficient.** (a) For §5.1–§5.7 the reviewer re-adds the listed numbers against the card inner height, confirms every text block is a fixed-height box (a literal px `height`, or the 24px badge token), and reads the clip rule to check it covers **descendants** of `.card` (`.card :not(.suit)`, or the enumerated `.t-list li`, `.t-group p`, `.t-table th`, `.t-table td`) and not only `.card > *`.
(b) Then the part that actually fails on the defect this document used to miss: inject an over-long string (≈2× §5's character budget) into one block at a time — a `#s3` `li`, a `#s4 .a-side` `.t-group p`, a `#s4 .a-wide` table cell — re-render `#/3` and `#/4` at 1280×720 by §7's command, and require **no ink outside that block's own px box**: nothing in the 16px separator run or over the next bullet, nothing in the neighbouring `.t-group`, no row taller than 44px, the surrounding card layout unchanged. The pre-fix CSS passed (a) — the sum adds up and `.card` does carry `overflow: hidden` — and failed (b); that is precisely why (b) is the check and (a) is not. The injected copy is a **mechanism** test and is expected to clip at its own box: the shipped copy must not clip at all, which is G4's line.
A9. Render `#/1`…`#/7` at 1280×720: the PNG IHDR is 1280×720 and the image is visibly non-blank — felt field, ≥ 1 card with a visible rim, nothing clipped or overlapping, no scrollbar; `#/7` shows three cards, `#/1` the title.
A10. Render at `--window-size=1600,1000`: the stage letterboxes with felt above and below, no scrollbar, no clipped card.
A11. Render `#/0`, `#/99`, `#/abc` and a bare `file://` path: every form lands in range — `#/0` → slide **1** (byte-identical to `#/1`), `#/99` → slide **7**, `#/abc` → 1, absent hash → 1. So `0` is **not** read as "clamp to the last slide": the digit string is parsed as written and clamped into 1..7, which is §6's `clamped into range` and nothing more; plus code review of the parse and clamp.
A12. **Code-review-only:** arrows, Space, Shift+Space, PageUp/PageDown, Home, End match §6 and clamp; wheel constants literally 60 / 250 / 400; click fractions literally `0.30`/`0.70` with the centre inert; and a held `Ctrl`/`Alt`/`Meta` returns before the key is read (§6). ## 8. Rejected alternatives

| Rejected | Why it lost |
|---|---|
| A slides framework — reveal.js, impress.js, any vendored or CDN copy | A network fetch or a second file to lose on the talk laptop, and its DOM owns the theme: the card primitive and the 1280×720 budget would be fought instead of stated (D-118) |
| Texture from an inline SVG `feTurbulence` data-URI | Its `xmlns` necessarily contains an `http://` string, so "no network dependency" stops being a one-line grep; a 3px gradient crosshatch gives the felt weave wanted, at no decode cost |
| A fluid stage — `clamp()`/`vmin` sizes, no fixed surface — or CSS-only scaling | CSS cannot divide two lengths, so `min(vw/1280, vh/720)` needs JS anyway; and fluid makes "never overflows" a function of the window instead of a sum of px, the one property A8 must add up |
| One `<iframe>` per slide, scaled to the window | Nested documents, a second copy of the theme, and no shared hash; the single-file rule of D-118 is the point |
| Continuous scroll / `scroll-snap` instead of discrete slides | A stray scroll puts two slides on a projector mid-sentence (D-118 rejected) |
| `pushState`/`replaceState` for the slide index | Refused or unreliable on a `file://` document in the target browser; the hash is the one history write that always works and still leaves a back-entry (§6) |
| A Markdown/JSON source plus a build step | A toolchain on the talk machine to edit text, and a stale `index.html` when it is not run (D-118 rejected) |
